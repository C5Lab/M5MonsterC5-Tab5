# USB ACK32 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the unreliable one-byte USB block acknowledgement with a negotiated, CRC-protected 32-byte ACK32 frame while leaving Grove and M-BUS on their existing one-byte replies.

**Architecture:** JanOS owns ACK32 construction and selects it only when the `receive` command contains `ack32`. Tab5 requests that mode only for USB, validates `READY ack_size=32`, reads one complete fixed-size reply, and verifies its status, block index, committed offset, and CRC before advancing. CRACK/1 capability protocol 3 makes the wire-format dependency explicit; the JanOS development version remains 1.7.5.

**Tech Stack:** ESP-IDF C, FreeRTOS UART/USB CDC transport, CRACK/1, host-side GCC C tests.

**Spec:** `docs/superpowers/specs/2026-09-20-usb-ack32-design.md`

## Global Constraints

- Do not build either firmware; only host tests may be compiled and run.
- ACK32 is exactly 32 bytes and uses the layout in the approved spec.
- Tab5 requests ACK32 only on USB; Grove and M-BUS retain one-byte ACK/NAK/CAN replies.
- JanOS advertises CRACK/1 protocol 3 and development version 1.7.5.
- Tab5 requires the JanOS 1.7.5 development build and CRACK/1 protocol 3.
- Existing resumable transfer and automatic DIAG behavior remain active.
- Preserve unrelated dirty-worktree changes in both repositories.

```c
if (usb_cdc) {
    uint8_t frame[HS_REMOTE_ACK32_SIZE];
    hs_remote_ack32_t ack;
    bool received = hs_crack_remote_read_exact_bytes(
        worker, frame, sizeof(frame), ack_timeout);
    accepted = received && hs_remote_ack32_parse(frame, sizeof(frame), &ack) &&
               ack.status == JANOS_UART_FT_ACK &&
               hs_remote_ack32_matches(&ack, index, offset + length);

    /* existing one-byte ACK/NAK/CAN path */
}
```
